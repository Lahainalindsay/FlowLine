# FlowLine — Finish the Existing Product and Launch It

Work from the CURRENT `Lahainalindsay/FlowLine` repository and the existing Replit project.

DO NOT rebuild this project from scratch.

DO NOT simplify or remove advanced functionality merely to make the codebase smaller.

DO NOT migrate away from the current architecture.

Preserve the existing:

* React/Vite frontend
* Express API
* PostgreSQL
* Drizzle ORM
* Clerk authentication
* OpenAPI/generated clients
* server-authoritative timer architecture
* realtime/multi-device capabilities
* display pairing
* messages
* cues
* imports
* history
* billing infrastructure
* existing advanced features

The application is already more advanced than a bare StageTimer clone.

The objective now is:

# MAKE THE EXISTING PRODUCT RELIABLE, COMPLETE, POLISHED, DEPLOYED, AND LAUNCHABLE.

Do not spend this task inventing more roadmap features.

---

# PRODUCT

Customer-facing name:

**FlowLine**

Positioning:

**Keep every moment on schedule.**

FlowLine is a professional synchronized timing and run-of-show platform.

It should work well for:

* live events
* conferences
* presentations
* meetings
* public comments
* churches
* livestreams
* broadcasts
* debates
* workout/video creators
* other structured timed sequences

These are NOT separate applications.

Use the same:

Event → Rundown → Segment → Timer → Display

architecture.

---

# PRIORITY 1 — MAKE EVENT CREATION BULLETPROOF

A new authenticated user must be able to:

1. Sign up.
2. Sign in.
3. Create an Event.
4. Open the Event.
5. Refresh.
6. Still see the Event.

Event creation must never silently fail.

Show useful errors.

Server must enforce ownership.

Do not trust client-provided ownership IDs.

Ensure database initialization is transactional where appropriate.

---

# PRIORITY 2 — RUN OF SHOW

Rundown functionality must be excellent.

Users must be able to:

* add segment
* edit segment
* delete segment
* reorder segments
* duplicate where supported
* set duration
* set title
* set speaker/name
* set timer mode
* set warning thresholds if supported
* move directly between segments

Preserve import functionality.

If CSV/import already exists, make it reliable.

If advanced scheduling functionality already exists, preserve it.

---

# PRIORITY 3 — TIMER

The timer is mission-critical.

Keep server-authoritative state.

Never make browser-local ticking authoritative.

Required:

* countdown
* count-up
* overtime
* start
* pause
* resume
* reset
* +1 minute
* -1 minute
* next segment

Preserve additional timer modes if already implemented and stable.

Timer must derive displayed state from authoritative timestamps/state.

It must survive:

* refresh
* reconnect
* temporary network loss
* switching devices

Timer controls must reject invalid transitions safely.

---

# PRIORITY 4 — MULTI-DEVICE SYNCHRONIZATION

FlowLine should be demonstrably good at this.

Test with at least:

## Device A

Operator

## Device B

Speaker display

## Device C

Stage/backstage display

Changes must propagate quickly and accurately.

Test:

* start
* pause
* resume
* reset
* +1
* -1
* next segment
* message
* cue

Then disconnect Device B from the network.

Reconnect it.

Expected:

* it requests authoritative state
* it catches up
* no permanent drift
* no duplicate timers
* no stale state overwrites

---

# PRIORITY 5 — MULTIPLE OPERATORS

If the existing architecture supports multiple operators, KEEP IT.

Test:

* Operator A opens Event
* Operator B opens same Event
* both observe same runtime
* A changes timer
* B receives update
* stale mutations cannot silently overwrite newer state

Do not remove concurrency/version protection.

# PRIORITY 7 — PAIRING

Preserve QR and short-code pairing.

Make it easy:

Operator:

Add Display
→ Choose Display Type
→ QR + Pairing Code

Guest:

Open pair screen
→ enter code or scan QR
→ connected

Security:

* display credentials scoped
* read-only
* revocable
* short code one-time
* expired codes fail
* invalid codes fail
* display token cannot perform operator mutations
