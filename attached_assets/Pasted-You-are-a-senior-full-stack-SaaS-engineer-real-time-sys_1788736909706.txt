REAL-TIME TIMER ENGINE

This is one of the most important parts of the application.

The server must be authoritative.

Do not implement the production timer by decrementing a database integer every second.

Instead persist enough state to calculate accurate elapsed/remaining time from timestamps.

Suggested timer state fields:

status
configuredDurationMs
startedAt
pausedAt
accumulatedElapsedMs
lastCommandAt
version

Statuses:

IDLE
RUNNING
PAUSED
COMPLETED

For a countdown:

remaining time should be derived from server timestamps.

For a count-up timer:

elapsed time should be derived from server timestamps.

Timer commands must include:

START
PAUSE
RESUME
RESET
COMPLETE
ADD_TIME
SUBTRACT_TIME
NEXT_SESSION

Clients should receive authoritative state from the server.

All connected displays must derive the visible timer from that authoritative state.

Implement protection against conflicting commands from multiple operators.

Use monotonic/version sequencing or another concurrency-safe design.
